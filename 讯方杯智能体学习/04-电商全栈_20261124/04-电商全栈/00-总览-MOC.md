## 🔗 贯穿全课的五条主线

### 线索一：**「业务规则才是需求的灵魂」**

```text
第1章  金额必须后端重算，不信前端
第1章  价格快照，防止商品调价影响历史订单
第2章  products → order_items 用 RESTRICT
第4章  事务保证订单与库存一致
```

> 🎯 这一整条线都在回答一个问题：**怎么保证数据是对的**。

### 线索二：**「约束越严，数据越可信」**

| 层 | 手段 |
|---|---|
| 数据库层 | NOT NULL · UNIQUE · **DECIMAL** · **ENUM** · 外键 |
| 应用层 | 参数校验 · **参数化查询** · 事务 |

> 💡 第2章讲数据库约束，第4章讲"两道防线"——**它们是同一个思想的两次出现**。

### 线索三：**「跨域和 localhost 是新手最常卡的两个坑」**

```text
同源三要素：协议 + 域名 + 端口，全同才同源
localhost：始终指向当前设备，真机要用局域网 IP
```

> 这两个问题有个共同特征：**不报错，只是"没反应"** —— 所以特别难查。

### 线索四：**「测失败路径，才叫专业测试」**

```text
第1章  原型验收要看空状态、加载状态、错误状态
第5章  把数量改成 9999，验证的是"该失败时能否失败"
```

> 🎯 **正常人测成功路径，专业开发者测失败路径。**

### 线索五：**「AI 出建议，人做决策」**

| 阶段 | AI 能做 | 人必须做 |
|---|---|---|
| 需求 | 整理清单、识别遗漏 | **优先级决策、规则确认** |
| 数据库 | 生成 ER 和建表 SQL | 判断设计是否合理 |
| 前端/后端 | 生成模式化代码 | **补充业务判断和异常分支** |
| 交付 | 盘点、一致性核查 | **确认改文档还是改代码** |

> 💡 **注意「AI 不能做什么」那一列** —— 全是**需要担责的判断**。

## 🎯 四张速查表

### 业务规则（第1章）

| 规则 | 要点 |
|---|---|
| 金额 | 后端重算，**不信前端** |
| 订单 | 记录**价格快照** |
| 状态 | 待支付→已支付→已发货→已完成，**不可逆** |
| 取消 | 仅待支付可取消，取消**释放库存** |
| 库存 | 超库存明确提示，**不静默截断** |

### 建表六决策（第2章）

| 决策 | 结论 |
|---|---|
| 字符集 | **utf8mb4**（utf8 只有 3 字节） |
| 金额 | **DECIMAL(10,2)**，绝不用 FLOAT |
| 状态 | **ENUM**，校验下沉到数据库 |
| 时间 | DEFAULT + ON UPDATE 自动维护 |
| 订单→详情 | **CASCADE** |
| 商品→详情 | **RESTRICT** |

### 绑定方式（第3章）

| 场景 | 用什么 |
|---|---|
| 文本内容 | `{{ }}` |
| 标签属性 | `:src="x"` |
| 双向绑定 | `v-model` |
| 事件 | `@click` |
| 移动端单位 | **rpx**（750rpx = 屏宽） |

### 报错速查（第4-5章）

| 现象 | 排查 |
|---|---|
| 服务起不来 | 语法错误（逗号、括号） |
| `EADDRINUSE` | 端口被占用 |
| `req.body` 是 undefined | `express.json()` 没挂或挂晚了 |
| 页面空白无报错 | **字段名不一致** / **跨域** |
| Console 有 CORS 红字 | 端口/域名不同源 |
| 真机请求全失败 | 用了 localhost |
