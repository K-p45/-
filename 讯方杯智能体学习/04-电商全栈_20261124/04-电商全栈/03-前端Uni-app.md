## 🎬 一、为什么用跨端框架

![[1007-Uni-app与Vue.mp4]]

### 原生分端开发的痛

```text
iOS（Swift）+ Android（Kotlin）+ 小程序（原生语法）
= 三套代码、三个团队、三份 bug 清单
```

> **改一个价格展示逻辑，要在三个地方各改一遍并各自测试。**

### Uni-app 的价值主张

| | 原生分端 | Uni-app |
|---|---|---|
| 代码库 | 三套 | **一套 Vue** |
| 改一个逻辑 | 三处都改 + 分别测 | **改一处，多端重编译** |
| 学习成本 | Swift/Kotlin/小程序语法 | **只需 Vue** |
| 原生能力 | 可深度调用 | 多数可覆盖，极少数需条件编译 |

> 🎯 **取舍**：以**业务功能为主、不需要深度调用硬件**的应用（如电商），Uni-app 优势明显。
> 如果需要深度调用原生能力，原生分端更强。

## 🎬 二、工程结构与两个关键配置

### 目录职责

| 目录/文件 | 职责 |
|---|---|
| `pages/` | 所有页面，每个子文件夹一个页面 |
| `static/` | 图片、字体等静态资源 |
| `App.vue` | 应用入口，**全局样式和生命周期** |
| `main.js` | JS 入口，初始化 Vue 实例 |
| **`manifest.json`** | 应用配置（**AppID、权限申请**） |
| **`pages.json`** | **页面路由、导航栏、TabBar** |
| `uni.scss` | 全局 SCSS 变量 |

### 两个 json 别搞混 ⭐

| 文件 | 管什么 |
|---|---|
| **manifest.json** | 应用级：AppID、权限 |
| **pages.json** | 页面级：路由、导航栏、TabBar |

### pages.json 三大配置块

| 配置块 | 作用 |
|---|---|
| **pages** | 注册页面路由（path + 导航栏标题） |
| **globalStyle** | 全局导航栏默认样式 |
| **tabBar** | 底部导航栏选项 |

> ⚠️ **最常见的坑**：
> `pages.json` 里登记了某页面，但对应的 `.vue` 文件不存在 → **编译直接报错**。
> **配置文件和物理文件必须一一对应。**

### 常用命令

```bash
npm run dev:h5      # 本地调试
npm run build:h5    # 生产构建
```

**模板选择**：选**默认模板**，不要选 hello uni-app 模板（那只是组件示例）。

## 🎬 三、Vue 单文件组件的三段式

### 为什么分三段

```vue
<template>  结构（长什么样）</template>
<script>    逻辑（怎么反应）</script>
<style>     样式（怎么好看）</style>
```

> **核心目的：把三种不同职责的代码解耦。**

| 收益 | 说明 |
|---|---|
| 修改互不影响 | 改样式不碰逻辑，改逻辑不碰样式 |
| 协作边界清晰 | 多人改同一组件时减少冲突 |
| 可维护性 | 新人能快速定位 |

> 💡 对比"HTML/CSS/JS 随手糊在一起"：三段式让**职责边界**变成物理隔离。

### 三种绑定方式（这块最容易混）

| 指令 | 用在哪 | 例子 |
|---|---|---|
| **插值 `{{ }}`** | **文本内容** | `{{item.name}}` |
| **v-bind（`:`) ** | **标签属性** | `<image :src="item.image" />` |
| **v-model** | **双向绑定** | `<input v-model="keyword">` |
| **v-on（`@`) ** | **事件** | `@click="handleSearch"` |

### v-model 为什么"打字就同步"

> 它在背后做**两件事**：
> 1. 把 `keyword` 的值显示到输入框
> 2. 监听输入事件，把用户输入**实时写回** `keyword`

**这就是双向绑定** —— 数据变驱动视图，视图变（用户输入）驱动数据。

```text
v-model 串联三件事：
输入框 ←→ keyword 数据 ←→ filteredList 计算属性 ←→ 列表刷新
```

> 💡 搜索框的经典用法：`keyword` 变了 → `computed` 自动重算 → 列表自动刷新。
> **一行 v-model 打通了输入框、数据和列表联动。**

### computed 为什么能自动重算

> 因为 Vue 的**响应式系统**会追踪 computed 依赖了哪些数据，**依赖变化时自动重新计算**。

### v-for 和 v-if

| 指令 | 用途 |
|---|---|
| **v-for** | 列表渲染 |
| **v-if** | 条件渲染 |

> ⚠️ **不要在同一元素上同时用 v-for 和 v-if** —— v-for 优先级更高，会导致逻辑混乱。

### rpx 而不是 px ⭐

> **移动端适配的关键**：`rpx` 是**响应式单位**，会根据屏幕宽度自动缩放。

```text
750rpx = 屏幕宽度（在任何设备上）
```

> 🎯 **用 px 的后果**：在 375px 宽的小屏上，一个 300px 的卡片正好；
> 在 414px 的屏上就显得偏小。**rpx 让设计稿在任何屏上都等比缩放。**

## ❓ 自测

1. Uni-app 相比原生分端开发的核心优势是什么？
2. manifest.json 和 pages.json 分别管什么？
3. `{{ }}`、`v-bind`、`v-model` 分别用在哪？
4. 为什么搜索框用 v-model 后列表会自动刷新？
5. 移动端为什么用 rpx 而不是 px？

<details>
<summary>参考答案</summary>

1. 一套 Vue 代码编译到多端，改一处逻辑所有端生效，学习成本只需掌握 Vue。
2. manifest.json 管应用级配置（AppID、权限）；pages.json 管页面路由、导航栏样式和 TabBar。
3. `{{ }}` 用于文本内容；v-bind 用于标签属性；v-model 用于表单双向绑定。
4. v-model 把输入实时写回 keyword，keyword 是 computed 的依赖，依赖变化触发计算属性重算，列表随之刷新。
5. rpx 是响应式单位，750rpx 恒等于屏幕宽度，能自动等比例适配不同尺寸的屏幕。
</details>
