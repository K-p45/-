## 🎬 一、Transformer 结构

![[301-自注意力机制.mp4]]

### 起源

2017 年 Google 论文**《Attention is All You Need》**：

> 完全用 Attention 替代 CNN / RNN，在机器翻译上取得突破。

### 整体结构

```text
输入句子
   ↓
[词嵌入 + 位置编码]  ← 两者相加
   ↓
┌──────── Encode r × 6 ────────┐
│  Multi-Head Attention        │
│  Add & Norm                  │
│  Feed Forward                │
│  Add & Norm                  │
└──────────────────────────────┘
   ↓ 编码矩阵 C
┌──────── Decoder × 6 ─────────┐
│  Masked Multi-Head Attention │  ← 不能看未来
│  Add & Norm                  │
│  Cross Attention (Q来自解码器,│  ← 看编码器输出
│                   K,V来自C)   │
│  Add & Norm                  │
│  Feed Forward / Add & Norm   │
│  Linear + Softmax            │
└──────────────────────────────┘
   ↓
输出下一个词
```

### 输入表示：为什么要加位置编码

```text
输入向量 x = 词嵌入(Word Embedding) + 位置嵌入(Position Encoding)
```

> 💡 **为什么必须加**：Transformer 用全局注意力，**天生不知道词的先后顺序**。
> 如果打乱输入顺序，注意力算出来的结果是一样的（只是换了行）。所以必须**显式告诉它「谁在第几位」**。
> 这是用 RNN 换注意力的直接代价。

## 🔍 二、自注意力（本章最核心）

### 三个矩阵：Q、K、V

| 矩阵 | 含义 | 类比 |
|---|---|---|
| **Q**（Query，查询） | 我要找什么 | 你搜索的关键词 |
| **K**（Key，键） | 我是什么 | 每篇文章的标题 |
| **V**（Value，值） | 我的实际内容 | 文章正文 |

**三个都来自同一个输入 X**，只是用三个不同的权重矩阵变换：

```text
Q = X · W_Q
K = X · W_K
V = X · W_V
```

### 计算公式

```text
              ⎛ Q · Kᵀ ⎞
Attention = softmax⎜────────⎟ · V
              ⎝  √d_k   ⎠
```

**四步走**：

| 步骤 | 操作 | 意义 |
|---|---|---|
| ① | **Q · Kᵀ** | 每个词的 Q 和所有词的 K 做内积 → n×n 的相关性矩阵 |
| ② | **÷ √d_k** | 缩放，防止内积过大导致 softmax 梯度消失 |
| ③ | **softmax** | 每行归一化成概率，和为 1 |
| ④ | **× V** | 按注意力权重加权求和所有词的值 |

> 💡 **为什么除以 √d_k**：维度越高，内积的数值越大。如果不缩放，softmax 会变得极度尖锐（几乎变成 one-hot），梯度就没了。**这是个纯粹的数值稳定性技巧，但至关重要。**

### 一句话理解

> **「苹果」这个位置的输出 = 所有词的值 V，按它们与「苹果」的相关程度加权平均。**
> 于是「苹果」的表示里，就混进了「派」或「发布」的信息 —— **它在上下文中被重新定义了**。

![[05-Transformer技术理论/幻灯片23.PNG]]

### 多头注意力（Multi-Head）

**做法**：并行做 h 次（通常 8 次）自注意力，每次用不同的 W_Q/W_K/W_V，然后把 h 个结果**拼接**，再过一层线性变换。

```text
        X
   ┌────┼────┬────┐
   ▼    ▼    ▼    ▼
 头1   头2   头3 ... 头8    ← 各自独立的 Q/K/V 权重
   └────┼────┴────┘
      Concat 拼接
        ↓
     Linear 降维到原维度
        ↓
        Z（和输入同维度）
```

**为什么需要多头**：

> 一个头只能学一种「相关方式」。多头让模型**同时**关注不同的关系 ——
> 一个头管语法（主谓一致），一个头管指代（它=苹果），一个头管语义。

> 🎯 输出维度与输入相同，所以**可以无限堆叠**。

## 🧱 三、Encoder 与 Decoder

### Add & Norm（残差 + 归一化）

```text
Add:  X + MultiHeadAttention(X)
Norm: LayerNorm(...)
```

| 组件 | 作用 | 解决什么 |
|---|---|---|
| **Add（残差连接）** | 把输入直接加到输出上 | **防止网络退化**，让梯度能直通到底层 |
| **Norm（层归一化）** | 把每层激活值标准化 | **加快收敛**，稳定训练 |

> 💡 残差连接就是第 2 章讲的**梯度消失**问题在这里的解法。**没有它，堆 6 层都费劲，更别说 96 层。**

### Feed Forward

一个**两层全连接**：第一层 ReLU，第二层不加激活函数。

```text
FFN(x) = max(0, x·W₁ + b₁)·W₂ + b₂
```

输出维度和输入一致。

### Decoder 和 Encoder 的三个区别

| 区别 | 说明 |
|---|---|
| **两个** Multi-Head Attention | 多了一个交叉注意力 |
| 第一个用了 **Masked** | 防止看到未来 |
| 最后有 **Softmax** | 预测下一个词的概率 |

### Masked 是怎么工作的（重点）

**为什么需要 Mask**：翻译时是**顺序**进行的，翻译第 i 个词时，只能看到前 i-1 个词。如果不遮住后面，就是**偷看答案**。

```text
Mask 矩阵（5 个词为例）
     <B>  I  have  a  cat
<B>   ✓   ✗   ✗    ✗   ✗
 I    ✓   ✓   ✗    ✗   ✗
have  ✓   ✓   ✓    ✗   ✗
 a    ✓   ✓   ✓    ✓   ✗
cat   ✓   ✓   ✓    ✓   ✓
     ↑    ↑
  只能看左边（含自己），右边全遮住
```

**操作位置**：在 **softmax 之前**，把要遮的位置设成 `-∞`，softmax 后自然变成 0。

> 🎯 **这个 Mask 就是「自回归」的技术实现**。GPT 系列全部是纯 Decoder 结构（只用带 Mask 的那部分），所以能一个词一个词往后生成。

### 第二个注意力的玄机

| 矩阵 | 来自哪里 |
|---|---|
| **Q** | Decoder 上一层的输出 |
| **K、V** | **Encoder 的编码矩阵 C** |

> 💡 这就是「编码器-解码器」的桥：**Decoder 在问（Q），Encoder 提供答案（K,V）**。
> 好处是 Decoder 每个位置都能利用**源句子的全部信息**，而且**不需要 Mask**。

## 🏋️ 四、大模型训练

![[302-训练全流程.mp4]]

### 数据：比架构更重要

> 同样的 Transformer 架构，**喂高质量数据的模型远胜于喂噪声数据的版本**。

**规模感**：

| 模型 | 数据量 |
|---|---|
| GPT-3 | 45TB（约 3000 亿 token） |
| LLaMA-2 | 2 万亿 token |
| LLaMA-3 | **15 万亿 token** |

**Chinchilla 定律**：最优数据量 ≈ **参数量的 20 倍**。
（7B 模型 → 至少 1400 亿 token）

### 数据来源与清洗

| 来源 | 内容 |
|---|---|
| **网页** | Common Crawl（GPT-3 有 60% 来自这里） |
| **书籍** | Books3（19.6 万册）、arXiv、PubMed |
| **代码** | GitHub（DeepSeek-Coder 采集 87 种语言） |
| **百科问答** | Wikipedia、Reddit、Stack Overflow |

**清洗三步**：

| 步骤 | 做法 | 效果 |
|---|---|---|
| **去重** | MinHash 检测近似重复 | 原始数据 30-50% 是重复 |
| **质量过滤** | 训个小分类器打分 | LLaMA-3 **只保留 5%** |
| **脱敏** | 删身份证、电话、有害内容 | 合规 |

> 🎯 **「只保留 5%」这个数字很震撼**。原始爬取的数据，95% 都被扔掉了。**数据清洗是真正拉开差距的地方。**

### 分词：BPE 与 WordPiece

| 算法 | 用在哪 | 策略 |
|---|---|---|
| **BPE** | GPT、LLaMA | 从字符开始，反复合并**最高频**的相邻对 |
| **WordPiece** | BERT | 合并标准是**最大化语言模型似然** |

**中文的特殊难题**：没有空格分隔。

```text
下雨天留客天留我不留
→ 下雨天 / 留客 / 天留 / 我不留
→ 下雨 / 天留客 / 天留我 / 不留
```

**两种处理方式**：

| 方式 | 优点 | 缺点 |
|---|---|---|
| 按字切 | 简单，词表小 | 序列变长，更耗算力 |
| **BPE 学中文子词** | 高频词整体编码 | 需要好语料 |

> Qwen-2.5 词表 15 万，含大量中文高频词 —— 这就是它中文效率高的原因之一。

### 预训练目标：预测下一个词

```text
输入：今天天气真
输出：好
```

> 💡 **这个目标看起来简单得可笑，但它是一切的基础。**
> 要准确预测下一个词，模型**必须**掌握语法、事实、推理模式。完美预测下一个 token 的模型，本质上掌握了语言里的全部信息。

**损失函数**：交叉熵（衡量预测分布与真实分布的差距）。

### 分布式训练：3D 并行

| 并行方式 | 切什么 | 特点 |
|---|---|---|
| **数据并行** | 切数据 | 每卡存完整模型，最简单 |
| **张量并行** | 切层内矩阵 | 一层拆到多卡 |
| **流水线并行** | 切层 | 不同层放不同卡 |

> **实际是三种同时用** —— DeepSeek-V3 用 2048 张 H800 组成集群。

### 混合精度训练

**思路**：

- 前向 + 反向用 **FP16/BF16**（快、省显存）
- 参数更新保留一份 **FP32 主副本**（保精度）

**效果**：速度 ×2，显存 ↓40%。

> 💡 **BF16 为什么比 FP16 更适合训练**：BF16 保留了和 FP32 相同的**指数范围**，不容易溢出。FP16 精度高但范围窄，训练时容易梯度爆炸。

### 训练监控

| 监控项 | 看什么 |
|---|---|
| **Loss 曲线** | 稳步下降 = 正常；突然飙升 = 数据问题或数值不稳 |
| **Checkpoint** | 每 1000 步存一次档，硬件故障可恢复 |

> 一个 70B 模型的 Checkpoint 约 **140GB**（FP16），存多个要几 TB。

## 🎯 五、对齐：从「能说」到「说好」

> 预训练完的模型就像一个**「博学但没有教养的人」** —— 知识满腹，但答非所问、胡编乱造。

**对齐目标**：**3H** —— Helpful（有用）、Honest（诚实）、Harmless（无害）。

### 第一步：SFT 监督微调

人工写高质量的「问题-答案」对（数千到数万条），继续训练。

> 💡 **InstructGPT 论文的震撼结论**：仅用 **13000 条**高质量标注数据，就让 **1.3B** 模型在用户偏好上**超过 175B 的原始 GPT-3**。
> **数据质量 >> 数据数量。**

### 第二步：RLHF 三步流程

![[06-大模型训练概述/幻灯片30.PNG]]

```text
① SFT     → 先教会它对话
② 训奖励模型 → 人类给回答排序，训出"打分器"
③ PPO 优化  → 用奖励模型给模型打分，强化得分高的回答
```

### 更简洁的替代：DPO 与 GRPO

| 方法 | 谁提出的 | 核心简化 |
|---|---|---|
| **DPO** | 斯坦福 2023 | **跳过奖励模型**，直接用偏好数据优化 |
| **GRPO** | **DeepSeek** | 不要奖励模型，**组内比较**哪个回答更好 |

> 🎯 **GRPO 是 DeepSeek-R1 的关键**：让模型对同一个问题生成一组回答，**组内互比**，强化好的。
> 特别适合数学、编程这种**有客观正确答案**的任务。这就是 R1 能追平 o1 的原因。

### 为什么 R1 轰动

> **只用强化学习**，不需要人工标注的推理过程数据，模型**自己学会了长思维链**。

## 🧩 六、MoE：大而不贵的秘密

![[303-MoE混合专家.mp4]]

### 核心思想

**稠密模型**：每个 token 都过同一个 FFN。
**MoE**：把 FFN 换成 **N 个专家**，每个 token **只激活其中几个**。

```text
稠密：token → [FFN]          所有参数都用上
MoE： token → [路由] → [专家3][专家7]   只激活 2 个
```

### 两个核心组件

| 组件 | 作用 | 类比 |
|---|---|---|
| **专家（Experts）** | 每个是一个独立的 FFN | 不同专科医生 |
| **路由（Router / Gate）** | 决定 token 给哪些专家 | 分诊台 |

### 稀疏性的价值

| | 稠密模型 | MoE |
|---|---|---|
| 总参数 | 70B | **671B** |
| 每次激活 | 70B（全部） | **37B**（5%） |
| 能力强弱 | 取决于 70B | 接近 671B 水平 |
| 计算成本 | 按 70B 算 | **按 37B 算** |

> 🎯 **一句话**：**总参数决定能力上限，激活参数决定单次成本。**
> 这就是「6000 亿参数、只花 37B 的钱」的原理。

### 专家容量管理

| 概念 | 说明 |
|---|---|
| **专家容量** | 单个专家在一个 batch 里最多接多少 token |
| **容量因子** | 默认 1 = 平均分配；>1 给不均衡留缓冲 |
| **溢出处理** | 超过容量的 token **跳过专家，走残差直连** |

### 共享专家

**问题**：多个专家都会重复存储相同的基础知识（比如语法），浪费。

**解法**：设几个**共享专家**，所有 token 都经过它；路由专家只学专精部分。最后两者输出**相加**。

> 共享专家数量通常**少于**路由专家 —— 太多会削弱稀疏性优势。

### 2025 年主流 MoE 对比

| 模型 | 总参数 | 专家数 | 激活策略 |
|---|---|---|---|
| 华为盘古 Ultra | 7180 亿 | 256 个路由 | 激活 8 个 |
| **DeepSeek-V3** | 6710 亿 | 256 个 | 激活 **37B** |
| Qwen3-Next-80B | 80B | 512 个 | 10 路由 + 1 共享 |
| Mixtral 8x7B | 46.7B | 8 个 | 激活 2 个 |
| Switch Transformer | 1.6T | 16384 个 | Top-k |

> 💡 **一个规律**：模型越大，专家越多。但专家越多，**路由决策越复杂、通信开销越大**。

## 🐋 七、DeepSeek 的三个杀手锏

| 技术 | 解决什么 | 效果 |
|---|---|---|
| **MLA**（多头潜在注意力） | KV Cache 太占显存 | 压缩 **93.3%** |
| **MoE 稀疏架构** | 参数大计算贵 | 671B 只用 37B |
| **GRPO** | 强化学习要奖励模型 | 组内比较，省掉奖励模型 |

### DeepSeek 演进

| 版本 | 时间 | 突破 |
|---|---|---|
| V1 | 2023 | 起步 |
| V2 | 2024.5 | **MLA** 首创 |
| V3 | 2024.12 | 671B MoE，成本 557 万美元 |
| R1-Zero | 2025.1 | 纯 RL，但格式差、语言混杂 |
| **R1** | 2025.1 | 加少量冷启动数据解决上述问题 |

> 🎯 **R1-Zero → R1 的修正很有启发**：纯强化学习能训出推理能力（证明可行），但**输出的格式很乱**。
> 加一点点冷启动数据（SFT），就把可读性解决了。**纯算法 + 少量人工，是最优解**。

## ❓ 自测

1. Transformer 为什么必须加位置编码？
2. 自注意力里的 Q、K、V 分别是什么含义？
3. 为什么要除以 √d_k？
4. Mask 操作在哪个环节做？为什么？
5. Decoder 第二个注意力的 K、V 来自哪里？
6. MoE 为什么能做到"参数大但成本低"？
7. GRPO 相比 RLHF 省掉了什么？

<details>
<summary>参考答案</summary>

1. 注意力是全局的、没有顺序概念，打乱输入顺序结果不变，必须显式编码位置信息。
2. Q 是"我要找什么"（查询），K 是"我是什么"（键），V 是"我的内容"（值）。
3. 维度越高内积数值越大，不缩放会让 softmax 变得过于尖锐，导致梯度消失。
4. 在 softmax 之前，把未来位置设为 -∞，softmax 后权重变 0，防止 Decoder 偷看未来的词。
5. K 和 V 来自 Encoder 输出的编码矩阵 C（Q 来自 Decoder 自己的上一层）。
6. 通过路由机制每次只激活一小部分专家，总参数量决定能力，激活参数量决定计算成本。
7. 省掉了奖励模型（reward model），改为对同一问题的多个回答做组内比较。
</details>
