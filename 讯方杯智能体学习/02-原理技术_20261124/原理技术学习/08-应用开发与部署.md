## 🎬 一、整体架构

![[801-Dify部署流程.mp4]]

```text
┌─────────────────────────────────────┐
│   Dify（应用层：工作流、知识库、Agent）  │  ← Docker 容器
└──────────────────┬──────────────────┘
                   │ HTTP 调用
┌──────────────────▼──────────────────┐
│   Ollama（模型层，端口 11434）        │  ← 本机运行
└──────────────────┬──────────────────┘
                   │
┌──────────────────▼──────────────────┐
│   DeepSeek / Qwen 等模型（GGUF 量化）  │
└─────────────────────────────────────┘
```

> 🎯 **这个架构的关键点**：Dify 跑在 Docker 里，Ollama 跑在宿主机上。
> **容器内部访问宿主机，必须用真实 IP，不能用 localhost** —— 这是最容易踩的坑。

## 🦙 二、Ollama：本地跑大模型

### 为什么用它

| 优点 | 说明 |
|---|---|
| 极简 | 一行命令 |
| 免费 | 本地推理零成本 |
| 隐私 | 数据不出本机 |
| 格式 | 自动下载 **GGUF 量化版** |

### 基本用法

```bash
# 安装后直接跑
ollama run deepseek-r1:7b

# 查看已下载的模型
ollama list

# REST API（默认端口 11434）
curl http://localhost:11434/api/generate -d '{"model":"deepseek-r1:7b","prompt":"你好"}'
```

### 显存需求对照（重要）

| 模型大小 | 内存需求 |
|---|---|
| 7B | **8 GB** |
| 13B | **16 GB** |
| 33B | **32 GB** |

> 💡 **跑之前先看自己机器**。7B 是多数消费级电脑的甜点档。

### 配 WebUI 界面

```bash
docker run -d -p 3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main
```

访问 `http://localhost:3000`。

## 🐳 三、Docker：为什么要用

### 核心价值

> **把应用和它的运行环境一起打包。**

| 好处 | 说明 |
|---|---|
| **环境一致性** | 消除服务器与开发机的差异 |
| **资源隔离** | 不污染宿主机 |
| **快速部署** | 几分钟搞定 |
| **易于管理** | 一条命令启停 |

> 💡 **Dify 依赖很多服务**（数据库、Redis、向量库……），手动装极其痛苦。**Docker Compose 一条命令全搞定** —— 这就是为什么官方只推荐 Docker 部署。

### 常用命令速查

| 目的 | 命令 |
|---|---|
| 运行容器 | `docker run -d -p 8080:80 nginx` |
| 查看运行的容器 | `docker ps` |
| 查看所有容器 | `docker ps -a` |
| 停止 | `docker stop <名称>` |
| 启动 | `docker start <名称>` |
| **启动整套** | `docker-compose up -d` |

### 参数解释

```bash
docker run -d -p 8080:80 nginx
#          │  │
#          │  └─ 端口映射：宿主机8080 → 容器80
#          └──── 后台运行
```

## 🐳 四、Dify 部署实战

### 为什么要配镜像源

国内拉 Docker 镜像很慢或失败，**必须配置镜像加速**。

配置文件 `/etc/docker/daemon.json`（Linux）：

```json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.mirrors.ustc.edu.cn",
    "https://docker.nju.edu.cn"
  ]
}
```

重启生效：

```bash
systemctl daemon-reload
systemctl restart docker
```

> 💡 **镜像源经常失效**。课程给了 10 多个备选，一个不行就换下一个。

### 部署步骤

```bash
# 1. 装 Docker
sudo apt-get update
sudo apt-get install ca-certificates curl

# 2. 配置镜像源
sudo nano /etc/docker/daemon.json

# 3. 克隆 Dify
git clone https://github.com/langgenius/dify.git
cd dify/docker

# 4. 复制配置并启动
cp .env.example .env
docker-compose up -d

# 5. 访问 http://localhost       （首次要设置管理员账号）
```

### 连接本地 Ollama（关键配置）

**问题**：Dify 在容器里，Ollama 在宿主机，容器里访问不到 `localhost:11434`。

**解法**：填**本机的真实局域网 IP**。

```text
Dify 设置 → 模型供应商 → Ollama
基础 URL：http://192.168.x.x:11434      ← ⚠️ 不能写 localhost
```

**Windows 上还要做端口转发**：

```cmd
netsh interface portproxy add v4tov4 listenport=11434 listenaddress=0.0.0.0 connectport=11434 connectaddress=127.0.0.1
```

> 🎯 **这是本章最容易卡住的地方**。
> 三个检查点：
> 1. `netstat -ano | findstr 11434` 确认端口在监听
> 2. Ollama 要监听 `0.0.0.0` 而不只是 `127.0.0.1`
> 3. 防火墙放行

## 🎛️ 五、Dify 能力全景

### 四大核心功能

![[15-Dify平台简介/幻灯片19.PNG]]

| 功能 | 说明 |
|---|---|
| **可视化工作流引擎** | 拖拽编排业务逻辑，无需写代码 |
| **多模型兼容** | 支持 GPT、DeepSeek、Qwen 等 |
| **智能 RAG 引擎** | 文档解析、检索增强、**精准溯源降幻觉** |
| **开放插件生态** | 50+ 工具，支持自定义 |

### 解决什么痛点

| 传统开发 | 用 Dify |
|---|---|
| 手动收集、清洗、标注数据 | 平台提供工具 |
| Prompt 调试没反馈 | **所见即所得**，实时调试 |
| 手动处理长上下文嵌入、向量库 | **自动处理** |
| 应用监控缺失 | 实时监控 + 完整日志 |
| 微调数据准备繁琐 | 批量导出标注数据集 |

### 典型应用场景

- 企业知识管理
- 24 小时智能客服
- 数据分析与决策支持

### 发布渠道

| 渠道 | 用途 |
|---|---|
| 网页 | 内部试用 |
| 嵌入式（iframe） | 挂到已有网站 |
| API | 接入自有系统 |

> 💡 **注意**：每次使用 Dify，都要先**开启 Docker** 并启动容器。
