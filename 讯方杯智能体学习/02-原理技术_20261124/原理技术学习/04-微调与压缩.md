## 🎬 一、微调：让通才变专家

![[401-微调与LoRA.mp4]]

### 微调到底改变了什么

**真实例子（医疗问答）**：

```text
输入：医生，我最近一直咳嗽，嗓子也有点痛，能推荐一些药物吗？

原始模型：我建议您先去看医生，以便得到更准确的诊断和治疗建议。
         （正确但没用 —— 每句话都是这个回答）

微调后：  根据您的描述……如果是干咳，可以尝试右美沙芬类镇咳药，
         如福尔可定口服液或右美沙芬糖浆。如果有痰，……
         （专业、具体、可直接参考）
```

> 🎯 **微调给的不是「知识」，而是「行为方式」**。
> 原始模型知道右美沙芬是止咳药，但它不知道**在什么场合、用什么口吻、按什么结构**说出来。

### 数据格式：指令微调三件套

```text
instruction（指令）  你是一位医学专家，请回答以下问题
input（输入）        我最近一直咳嗽……
output（输出）       根据您的描述……
```

### 灾难性遗忘（必考重点）

**问题**：只用领域数据微调，模型会把通用能力忘掉。

**课程实测数据**（医疗领域微调）：

| 通用 : 领域 | 通用能力（大学各科） | 医疗能力（临床测试） | 结论 |
|---|---|---|---|
| 1 : 0 | 90+ | **20-30** ❌ | 只会通用，不会医疗 |
| **1 : 1** | **80-90** ✅ | **80-90** ✅ | **两全其美** |
| 0 : 1 | **20-30** ❌ | 80-90 | **灾难性遗忘** |

> 💡 **这张表是本章最有价值的实证**。
> 微调时必须**混入通用数据**（1:1 左右），否则模型会「学会专科，忘掉常识」。
> 中间那行才是正确做法。

## 🔧 二、微调方法：全参 vs PEFT

### 全参数微调的问题

| 问题 | 说明 |
|---|---|
| **成本高** | nB 模型全参微调显存 ≈ **8n GB**（参数+梯度+优化器状态） |
| **效率低** | 训练耗时长 |
| **易过拟合** | 数据少时，训练集很好但泛化差 |

> 一个 7B 模型全参微调要 56GB 显存 —— 至少 4 张 A100。

### PEFT：只训一小部分参数

**思路**：把大部分参数**冻结**，只训练一小块。

| 类别 | 方法 | 原理 |
|---|---|---|
| **添加型** | **Adapter** | 在 Transformer 块里插入小模块 |
| | Soft Prompts | 只学提示向量 |
| **选择型** | Freeze | 冻结部分层 |
| **重参数化** | **LoRA** ⭐ | 低秩矩阵近似 |

### LoRA：最重要的一种（必须理解）

**核心假设**：
> 微调时权重的**变化量 ΔW 是低秩的** —— 可以用两个小矩阵相乘近似。

**数学表达**：

```text
h = W₀x + ΔWx = W₀x + BAx

W₀ : 原始权重（冻结不动）
B, A : 两个小矩阵（可训练）
r : 秩，通常 8-64
```

**参数省多少（课程例题）**：

```text
原始矩阵：d = 768
  → 全参数 = 768 × 768 = 589,824

LoRA（r = 16）：
  A: 768 × 16 = 12,288   （降维）
  B: 16 × 768 = 12,288   （升维）
  合计 = 24,576

优化效果：24,576 / 589,824 ≈ 4.2%，即训练参数减少 95%+
```

**LoRA 的三个优势**：

| 优势 | 对比对象 | 说明 |
|---|---|---|
| **支持更长输入** | Soft Prompts | 不占用输入的 token 位置 |
| **推理无额外延迟** | Adapter | 可以和原权重**合并** |
| **适用性高** | —— | 合并后代码与原始模型完全相同 |

> 🎯 **「推理无延迟」这点最关键**：训练完把 BA 加进 W₀，得到一个普通模型。
> 部署时完全不需要改任何代码 —— 这就是 LoRA 能成为业界标准的原因。

### 什么时候用哪种

| 场景 | 选择 |
|---|---|
| GPU 充足、数据量大 | 全参数微调 |
| GPU 有限、数据量小 | **PEFT / LoRA** |

**课程给的真实案例**：

| 模型 | 领域 | 方法 |
|---|---|---|
| Llama3.1 / Qwen2.5 / DeepSeek-R1 | 通用 | 全参数 |
| OceanGPT | 海洋 | **LoRA** |
| 中景 Zhongjing | 医疗 | **LoRA** |
| SecGPT | 网络安全 | **LoRA** |

> 规律很清楚：**通用大模型全参，垂直领域 LoRA**。

### 工具

| 工具 | 特点 | 适合 |
|---|---|---|
| **LLaMA-Factory** | 可视化界面、一键部署测试 | **新手** |
| **Swift** | 更快更省内存 | 有经验、追求效率 |

## 🗜️ 三、压缩：让模型跑得起

![[402-量化与蒸馏.mp4]]

### 问题有多大

| 模型 | FP16 显存需求 |
|---|---|
| LLaMA-2-7B | 14 GB |
| LLaMA-2-70B | **140 GB**（超出单张 A100-80G） |
| DeepSeek-V3 (671B) | **1.2 TB**（16 张 A100） |

一张 A100-80G 约 **10 万元**。

**推理速度也不够**：70B 模型在单卡上生成一个 token 要 50-100ms，**每秒只能输出 10-20 个字**。100 个用户并发时，单卡每秒处理不到 1 个请求。

### 量化：最常用的压缩

**类比**：RAW 格式照片 50MB → JPEG 只有 5MB，肉眼看不出差别。

```text
FP32（4 字节）→ INT8（1 字节）→ INT4（0.5 字节）
体积缩小 4-8 倍
```

**实际效果（LLaMA-2-7B）**：

| 精度 | 显存 | 能跑在 |
|---|---|---|
| FP16 | 14 GB | A100 |
| INT8 | 7 GB | RTX 3060 |
| INT4 | **3.5 GB** | **RTX 3060（12G）绰绰有余** |

### PTQ vs QAT

| | PTQ（训练后量化） | QAT（量化感知训练） |
|---|---|---|
| 何时做 | 训练完直接量化 | 训练时就模拟量化 |
| 优点 | **简单快速**，不需要重训 | 精度损失小 |
| 缺点 | 极低精度（4bit）时精度掉得多 | 需要额外训练 |
| 常用度 | ⭐⭐⭐ **最常用** | 特殊场景 |

### 三种主流格式

| 格式 | 特点 | 用在哪 |
|---|---|---|
| **GPTQ** | 逐层量化 + 误差补偿，INT4 效果好 | HuggingFace 最常见 |
| **AWQ** | 保护「重要权重」，同精度下更好 | 质量优先 |
| **GGUF** | 专为 **CPU 推理**优化，Q2-Q8 可选 | **Ollama 用的就是它** |

### 精度怎么选

| 精度 | 影响 | 建议 |
|---|---|---|
| INT8 | 几乎无损（<1%） | 显存够就选它 |
| **INT4** | 掉 2-5% | **消费级显卡最佳** |
| INT3/INT2 | 明显下降 | 仅研究用 |

> 🎯 **决策口诀**：
> 显卡够 → INT8
> 消费级显卡 → INT4（AWQ 或 GPTQ）
> 只有 CPU → GGUF 的 **Q4_K_M**

### 知识蒸馏

**思想**：用大模型（教师）训练小模型（学生）。

**关键区别**：
> 学生学的**不是标准答案，而是老师的输出分布** —— 也就是**老师「怎么思考」**。

**著名案例**：

| 案例 | 效果 |
|---|---|
| DistilBERT | 60% 参数，保留 **97%** 性能 |
| **DeepSeek-R1 蒸馏** | 671B → 7B / 14B / 32B 系列 |

> 💡 **R1 蒸馏的意义**：把 671B 的推理能力「压缩」到 7B，**普通显卡就能跑出接近 o1 的推理**。

### 剪枝

| 类型 | 做法 | 效果 |
|---|---|---|
| **非结构化** | 单个权重置零 | 稀疏，但硬件支持有限 |
| **结构化** | 移除整个神经元/注意力头 | **直接加速** |

> 现实里剪枝通常**和量化、蒸馏组合用**，很少单独使用。

### QLoRA：两个一起上

```text
基础模型 → 量化到 4bit（省显存）→ 在上面做 LoRA（省训练参数）
```

> 效果：**一张 RTX 4090 就能微调 7B 模型**，而全参微调要 4 张 A100。

## ⚡ 四、推理优化：怎么让生成更快

![[403-推理加速技术.mp4]]

### KV-Cache（必考）

**问题**：生成第 N 个词时，要「回顾」前面所有词的注意力。每次都重算，太浪费。

**解法**：把算过的 **K 和 V 缓存**起来，下次直接查。

```text
没有 Cache：生成每个 token 都要重算全部 → O(n²)
有 Cache：  只算新 token → O(n)
```

**代价**：额外显存。7B 模型 + 2048 上下文，KV-Cache 约 **2-4 GB**。

> 💡 **DeepSeek 的 MLA 就是冲着这个去的** —— 把 KV Cache 压缩 93.3%。这是省推理成本最直接的一招。

### FlashAttention

**问题**：标准注意力要生成 N×N 矩阵（4096 token → 1677 万个元素），在显存和缓存之间反复搬运，是「内存墙」。

**解法**：斯坦福 Tri Dao 团队提出，**分块计算，减少 HBM 读写**。

### 推理框架对比

| 框架 | 核心创新 | 适合 |
|---|---|---|
| **vLLM** | **PagedAttention**（像操作系统管内存一样管 KV-Cache），利用率 95%+ | **生产环境吞吐最高** |
| **TensorRT-LLM** | NVIDIA 官方，算子深度优化 | 追求极致速度 |
| **Ollama** | 一行命令跑模型，基于 llama.cpp | **个人开发者** |

**Ollama 有多简单**：

```bash
ollama run deepseek-r1:7b
```

REST API 默认端口 `11434`：

```python
import requests
requests.post("http://localhost:11434/api/generate",
              json={"model": "deepseek-r1:7b", "prompt": "你好"})
```

### 连续批处理

**问题**：传统批处理要等一批全部完成才能处理下一批。一个长请求会拖累所有人。

**解法**：完成的随时退出，新的随时加入。

> 效果：GPU 利用率从 **30-50% → 80%+**。

### 投机采样

**思路**：
```text
小模型（草稿）快速写几个候选 → 大模型一次性验证
```

**为什么快**：大模型验证多个 token 的成本，和生成单个 token **差不多**。草稿猜得准就有 **2-3 倍加速**。

### 端侧部署

**llama.cpp** —— 纯 C/C++，不依赖 Python 和 CUDA，能在**几乎任何设备**上跑：服务器、MacBook、树莓派、手机。

### 国产方案：昇腾 + MindIE

| 项目 | 情况 |
|---|---|
| 昇腾 910B | 约 300 TFLOPS（FP16），接近 A100 |
| MindIE | 华为推理引擎，已适配 LLaMA/Qwen/DeepSeek |
| 集成 | KV-Cache 优化、连续批处理 |

> 政府和国企的国产化项目，**昇腾 + MindIE 是目前最成熟的方案**。

4. LoRA 为什么说"推理无额外延迟"？
5. INT8 和 INT4 分别适合什么场景？
6. 知识蒸馏里学生学的是什么？
7. KV-Cache 节省了什么？代价是什么？

<details>
<summary>参考答案</summary>

1. 不是新知识，而是领域的行为方式——专业术语的用法、回答的结构和口吻。
2. 只用领域数据微调会导致通用能力大幅下降。解决方法是按约 1:1 混入通用数据。
3. 因为假设权重变化量是低秩的，用两个小矩阵 A(768×r) 和 B(r×768) 的乘积近似，参数量远小于原矩阵。
4. 训练完成后可以把 BA 加进原权重 W₀ 合并成一个模型，部署时与原始模型完全一致。
5. INT8 用于显存充足的场景（几乎无损）；INT4 用于消费级显卡（掉 2-5% 性能，性价比最高）；纯 CPU 用 GGUF 的 Q4_K_M。
6. 学的不是标准答案，而是教师模型的输出概率分布，也就是"老师怎么思考"。
7. 节省了重复计算前面所有 token 注意力的开销；代价是额外的显存占用。
</details>
