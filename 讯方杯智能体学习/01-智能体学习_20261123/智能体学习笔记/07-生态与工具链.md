## 🎬 四条扩展路线

![[07-四条扩展路线.mp4]]

```text
① 纯提示词 ──► ② +知识库 ──► ③ +插件 ──► ④ +API/工作流
   有风格         懂私事          有手脚         能编排
```

| 路线 | 解决什么 | 代价 |
|---|---|---|
| ① 提示词 | 说话方式、回答风格 | 最轻，改一句就生效 |
| ② 知识库 | 不知道你的私有资料 | 要维护文档、检索质量决定成败 |
| ③ 插件 | 只会说，不会做 | 要配置权限、错误处理 |
| ④ API/工作流 | 流程太长需要精确控制 | 要开发、要调试 |

## ① 提示词在 Agent 中的作用

提示词是**最便宜的杠杆**。在 Agent 里它承担四件事：

| 作用 | 例子 |
|---|---|
| 定角色 | 「你是资深法务顾问」 |
| 定流程 | 「先确认需求，再给方案，最后确认」 |
| 定边界 | 「不确定就说不确定，不要编」 |
| 定格式 | 「输出 Markdown 表格」 |

> 💡 **思维链提示在 Agent 里的特殊价值**：Agent 需要**规划**下一步做什么，而规划本身就是推理任务。**要求它先输出思考再调用工具，成功率会明显提升** —— 这也是 ReAct 模式的核心。

---

## ② 知识库：从「通才」到「专家」


| 维度 | 有无知识库的差别 |
|---|---|
| 回答依据 | 训练数据 vs **你的文档** |
| 时效性 | 截止日期 vs **最新** |
| 可溯源 | ❌ vs ✅ 能指出第几段 |
| 幻觉 | 常见 vs 大幅减少 |

> 💡 **核心机制回顾**（详见 [[05-Agent开发入门]]）：
> **检索 → 拼进提示词 → 生成**。所以知识库效果 = **检索质量 × 模型阅读能力**。
> **优化知识库，八成时间应该花在检索上**，而不是换模型。

---

## ③ 插件：给 Agent 装手脚

| 插件类型 | 典型能力 | 没有它会怎样 |
|---|---|---|
| 搜索 | 查实时信息 | 答案停留在训练数据 |
| 计算/代码 | 精确计算、跑代码 | 算数出错 |
| 数据库 | 查业务数据 | 只能瞎猜 |
| 办公 | 发邮件、建日程 | 只能给你"建议" |

> 🎯 **插件是 Agent 与 Chatbot 的分水岭**。没有插件，再聪明的模型也只是个"键盘侠"。

## ④ API 集成与代码节点

适合**步骤固定、需要精确控制**的流程。

```text
用户提问
  ↓
[判断意图]  ← 代码节点，精确分类
  ├─ 查订单 → [调 API] → [格式化]
  ├─ 售后咨询 → [知识库检索] → [生成]
  └─ 其他 → [转人工]
  ↓
[统一输出]
```

| 用代码节点 | 用提示词 |
|---|---|
| 需要 100% 确定性 | 需要灵活判断 |
| 复杂条件分支 | 简单分支 |
| 数据格式转换 | 自然语言生成 |

> 💡 **最佳实践**：**能确定的地方用代码，需要理解的地方用模型**。
> 比如"判断用户问的是订单还是退款"——用模型（自然语言）；"查到订单后拼接回复模板"——用代码（确定性）。**别让模型干它不擅长的精确活。**

## 📊 主流工具链对比

![[07-工具选型.mp4]]

| 工具 | 类型 | 适合 |
|---|---|---|
| **Coze** | 低代码平台 | 快速验证、非技术团队 |
| **Dify** | 开源可自部署 | 需要私有化 |
| **LangChain** | 代码框架 | 深度定制 |
| **LangGraph** | 图编排（见 [[06-多智能体系统]]） | 生产级多 Agent |
| **n8n** | 工作流自动化 | 连接已有系统 |

> 💡 **Coze 的独特优势**：**一站式**——模型、知识库、插件、发布渠道全在一个界面里配好。缺点也在这：**被平台锁定，深度定制受限**。
> 所以策略还是那句：**先用低代码验证，再决定要不要自己写。**

## ❓ 自测

1. 四条扩展路线分别解决什么问题？
2. 为什么说"插件是 Agent 与 Chatbot 的分水岭"？
3. 什么时候该用代码节点而不是提示词？
4. Coze 这类低代码平台的最大风险是什么？
5. 为什么说优化知识库应该重点优化检索？

<details>
<summary>参考答案</summary>

1. 提示词定风格、知识库懂私事、插件给能力、API/工作流做精确编排。
2. 没有插件，模型只能输出文字建议；有插件，它才能真正查询、计算、执行操作。
3. 需要 100% 确定性、复杂条件分支、数据格式转换的场景——这些是模型不擅长的精确活。
4. 平台锁定：深度定制受限，迁移成本高。
5. 知识库效果 = 检索质量 × 模型阅读能力，而检索才是短板；检索不到正确内容，再强的模型也只能瞎猜。
</details>
