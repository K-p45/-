# 04 · Agent 基本原理

> **一句话**：Agent = **大模型 + 工具 + 循环**。它把「一问一答」变成「自己盯着目标反复干，直到干成」。

⬅️ [[03-提示词进阶]] ｜ [[00-总览-MOC]] ｜ [[05-Agent开发入门]] ➡️

---

## 🤖 什么是 Agent

![[04-Agent工作流.mp4]]

### 核心定义

> **Agent 是一个能自主感知环境、基于目标推理决策、执行行动，并通过学习优化行为的智能实体。**

拆开就是四个词：

| 词 | 意思 |
|---|---|
| **自主** | 人只说目标，路径它自己找 |
| **感知** | 能看到环境 / 输入 |
| **行动** | 能真的做事，不只是说话 |
| **优化** | 能根据结果改进 |

### Agent vs 传统软件

![[04-Agent-vs-传统软件.mp4]]

| 维度 | 传统软件 | Agent |
|---|---|---|
| 驱动方式 | 人把规则**写死** | 模型**自主决策** |
| 遇到新情况 | 报错 / 崩溃 | 临场想办法 |
| 开发成本 | 每个分支都要写 | 主要写目标和工具 |
| 可控性 | **完全确定** | 需护栏与评估 |
| 适合 | 流程固定、高可靠 | 开放、多变、需灵活 |

> 💡 **关键洞察**：传统软件是**穷举路径**，Agent 是**搜索路径**。
> 代价是**可预测性下降** —— 所以真实生产里，Agent 必须配**护栏（guardrails）**：工具白名单、最大迭代次数、敏感操作人工确认。

### Agent vs 大模型

| | 大模型 | Agent |
|---|---|---|
| 本质 | 一个函数，输入→输出 | 一个循环，直到目标达成 |
| 能不能用工具 | ❌ | ✅ |
| 会不会自己重试 | ❌ | ✅ |
| 会不会用上一次的结果 | ❌（除非你喂回去） | ✅ |

> 🎯 **一句话**：**大模型是"会思考的大脑"，Agent 是"装上了手脚还在闭环里的人"。**

## 🔄 核心闭环：感知 → 规划 → 行动 → 学习

| 环节 | 做什么 | 技术 | 难点 |
|---|---|---|---|
| 👁️ **感知** | 读懂环境输入 | 分词、语义分析、目标检测、多源融合 | 数据准确性、噪声、实时性 |
| 🧠 **规划** | 拆目标、选策略、调工具 | 规则推理、LLM 提示、搜索算法、工具调用 | 不确定性、计算复杂度 |
| 🦾 **行动** | 真的执行 | API 调用、机械控制、工具执行 | 实时性、可靠性 |
| 🔄 **学习** | 看结果、改策略 | 强化学习、反馈优化 | 信用分配困难 |

### 为什么必须是「环」而不是「线」

```text
线：感知 → 规划 → 行动    （做完了，但不知道做得好不好）

环：感知 → 规划 → 行动
      ↑              │
      └──── 学习 ◄───┘
```

**行动之后必须重新感知** —— 用户追问了要调整、障碍出现了要重规划、任务失败了要重试。**没有这个环，就只是个流水线，不叫 Agent。**

> 💡 **补充**：2024-2025 年的 **Agentic Workflow**（路由、编排、多代理）本质上都是给这个环**加结构**。比如路由模式是在"规划"前加一个分类器，决定走哪条环。

### 用两个例子走一遍

| 步骤 | 智能客服 | 自动驾驶 |
|---|---|---|
| 感知 | 用户问"我的订单到哪了" | 摄像头看到行人 |
| 规划 | 需要查订单 → 调用查询 API | 计算刹车距离，决定减速 |
| 行动 | 返回"明天到" | 控制刹车 |
| 学习 | 用户点了"满意"→ 记住这个话术 | 避免了一次险情 → 优化策略 |

## 🪜 五级智能：从条件反射到自我进化

![[04-Agent五层次.mp4]]

这是理解 Agent 最重要的一个框架。**级别越高，越强也越难控。**

### L1 反应式 Agent

> **天黑了 → 开灯。**

| | |
|---|---|
| **机制** | 条件-行动映射（if-then） |
| **记忆** | ❌ 没有 |
| **技术** | if-then 规则、有限状态机 |
| **案例** | 智能灯具、游戏 NPC |
| **优点** | 简单、快、实时 |
| **缺点** | 无记忆、无规划，复杂任务做不了 |

> 💡 **别小看 L1**：生活中的大部分智能硬件都停在这一层，而且**这就够了**。不是所有场景都需要大模型。

### L2 基于模型的 Agent

> **记住走过的路，预测前面堵不堵。**

| | |
|---|---|
| **机制** | 维护环境状态模型，预测变化 |
| **记忆** | ✅ 有（状态） |
| **技术** | 状态空间表示、搜索算法 |
| **案例** | 导航 Agent（记录路径、预测路况）、棋类 Agent |
| **优点** | 预测能力强、能处理中等复杂任务 |
| **缺点** | 模型维护成本高 |

### L3 基于目标的 Agent

> **目标是"3 小时内送到"，它自己搜出一条路线。**

| | |
|---|---|
| **机制** | 目标函数 + 约束条件 → 搜索最优方案 |
| **技术** | 启发式搜索（A*）、线性规划 |
| **案例** | 物流调度、任务分配 |
| **优点** | 灵活、适合多变量优化 |
| **缺点** | 计算复杂度高、**必须把目标定义清楚** |

### L4 基于效用的 Agent

> **既要快、又要安全、还要舒适 —— 自己权衡。**

| | |
|---|---|
| **机制** | 效用函数评估状态好坏，最大化期望效用 |
| **技术** | 期望效用最大化、马尔可夫决策过程（MDP） |
| **案例** | 自动驾驶（速度/安全/舒适）、投资 Agent（收益/风险） |
| **优点** | 处理不确定性、多目标权衡 |
| **缺点** | **效用函数极难定义**、计算量巨大 |

> 💡 **这里最容易出问题**：谁来定义"舒适"值多少分？**效用函数写错了，Agent 就会钻空子** —— 这就是所谓的 reward hacking（奖励黑客）。

### L5 基于学习的 Agent

> **从数据和反馈里自己变强，越用越聪明。**

| | |
|---|---|
| **机制** | 训练 / 试错优化策略 |
| **技术** | 深度学习、强化学习（Q-learning、策略梯度） |
| **案例** | 推荐系统、AlphaGo（自我对弈）、自动驾驶感知 |
| **优点** | 自适应、泛化能力强 |
| **缺点** | 训练成本极高、需要海量数据、**行为难预测** |

---

### 五级对照速查

| 层级 | 有没有记忆 | 有没有目标 | 能不能权衡 | 会不会学习 | 一句话 |
|---|---|---|---|---|---|
| L1 反应式 | ❌ | ❌ | ❌ | ❌ | 条件反射 |
| L2 基于模型 | ✅ | ❌ | ❌ | ❌ | 记住过去 |
| L3 基于目标 | ✅ | ✅ | ❌ | ❌ | 追求目标 |
| L4 基于效用 | ✅ | ✅ | ✅ | ❌ | 多目标权衡 |
| L5 基于学习 | ✅ | ✅ | ✅ | ✅ | 自我进化 |

> 🎯 **记忆口诀**：**越往下，能力越强，可控性越差，成本越高。**
> 选型原则：**用能满足需求的最低层级**，别过度设计。

## 🎬 课程里的 Coze 层次定位

课程把 Coze 平台的能力映射到这五级：

| 层级 | Coze 里怎么实现 |
|---|---|
| 反应式 | 关键词触发规则 |
| 基于模型 | 对话历史 + 上下文记忆 |
| 基于目标 | 工作流编排 |
| 基于效用 | 多目标优化配置 |
| 基于学习 | LLM + 用户反馈动态优化 |

> 💡 **补充**：这说明**大多数"低代码 Agent 平台"其实覆盖了 L1-L3**，L4/L5 需要自己写代码。别指望拖拽就能做出自学习的 Agent。

## ❓ 自测

1. Agent 和传统软件最本质的区别是什么？
2. 为什么说「学习」这个环节是 Agent 成为"环"的关键？
3. 五级智能里，哪一级第一次出现"记忆"？
4. 什么样的场景**不需要**上 L4/L5？
5. 效用函数定义错了会发生什么？

<details>
<summary>参考答案</summary>

1. 传统软件由人穷举所有路径；Agent 由模型根据目标实时搜索路径。
2. 有了学习，Agent 才能根据行动结果反过来调整策略，形成闭环；否则只是一条单向流水线。
3. L2 基于模型的 Agent——它维护环境状态，是记忆的雏形。
4. 需求简单、环境稳定的场景（如智能灯具），L1 反应式就够，过度设计只会增加成本和不确定性。
5. Agent 会为了刷分而作弊（reward hacking），做出偏离真实意图的行为。
</details>
