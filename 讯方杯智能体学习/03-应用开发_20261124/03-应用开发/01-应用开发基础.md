## 🎬 一、模型怎么选

![[901-国产模型选型.mp4]]

### 主流的几个玩家

| 模型 | 开源 | 公司 | 特点 |
|---|---|---|---|
| **DeepSeek** | ✅ | 深度求索 | 架构创新，性价比之王 |
| **Qwen 通义** | ✅ | 阿里 | 规格最全，0.5B~72B |
| **GLM 智谱** | ✅ | 智谱 | 中文 NLP 强 |
| **Kimi** | ✅ | 月之暗面 | 超长文本 |
| 豆包 | ❌ | 字节 | 多轮对话、情感 |
| GPT / Claude | ❌ | OpenAI / Anthropic | 综合最强但贵 |

> 💡 **课程的判断**：国外模型在访问上有额外处理，而且**性价比不高**。
> 国内主流模型都兼容 OpenAI 接口，**换模型只是改两个参数** —— 这个设计后面会反复用到。

### 看懂模型版本标识（很实用）

| 标识 | 含义 | 例子 |
|---|---|---|
| **72B / 7B** | 参数量（B = 十亿） | Qwen2.5-72B 是 720 亿参数 |
| **1M / 128K** | **上下文窗口**（token 数） | 1M = 100 万 token 的上下文 |
| **Turbo** | 加速优化版，更快更省 | GPT-4 Turbo |
| **Preview** | 预览版，**不是正式商用版** | —— |
| **V / VL** | 支持视觉（图像/视频） | Qwen-VL |
| **Coder** | 代码专用 | Qwen2.5-Coder |
| **Reasoner / R1** | 推理增强，会输出思维链 | DeepSeek-R1 |

> 🎯 **选型第一步就是读懂这些后缀**。
> 「1M」是上下文窗口不是参数量 —— 这是考试常考的坑。

### 硬件：GPU / TPU / CPU

| 硬件 | 定位 | 谁做的 |
|---|---|---|
| **CPU** | 通用计算，什么都能干但都不快 | Intel / AMD / 鲲鹏 |
| **GPU** | 并行计算，AI 的主力 | NVIDIA / 昇腾 |
| **TPU** | 专为张量运算定制 | Google |

**算力怎么看**：`FLOPS` = 每秒浮点运算次数。
`1 TFLOPS = 1 万亿次/秒`。

> 💡 **选卡要看精度**：AI 训练和推理优先看 **FP16/BF16 算力**（如 H100 的 4 PFLOPS），而不是 FP32。

## 🏭 二、国产算力：昇腾这套东西

### 为什么需要它

x86 长期由 Intel/AMD 主导，但 **ARM 架构能效比更高**，特别适合 AI 推理这种高并发场景。

**华为的组合拳**：
```text
鲲鹏（ARM CPU）  →  负责通用计算
昇腾（NPU）      →  负责 AI 加速
```

> 💡 **一句话记住**：鲲鹏像 CPU，昇腾像 GPU/NPU。

### 达芬奇架构：三种计算单元

![[02-国产算力基础与DeepSeek生态/幻灯片11.PNG]]

| 单元 | 职责 | 工厂类比 |
|---|---|---|
| **Cube** | **矩阵乘法**，深度学习核心 | 主生产线，大批量标准化 |
| **Vector** | 向量运算（激活函数等） | 精加工车间 |
| **Scalar** | 标量运算（地址计算等控制逻辑） | 调度中心 |

> 🎯 **Cube 是最关键的** —— 深度学习 90% 的计算量都是矩阵乘法。
> 考试问"专门用于矩阵乘法的单元"，答案就是 Cube。

### 产品线：从端侧到云端

| 产品 | 场景 | 算力 |
|---|---|---|
| **Atlas 200/500** | 端侧边缘（摄像头、无人机） | 8-16 TOPS，功耗 10W |
| **Atlas 300I/300V** | 数据中心推理卡（PCIe） | 70-310 TOPS |
| **Atlas 800** | 云端训练服务器（8 颗 910） | 2P FLOPS |
| **Atlas 900** | 超大规模训练集群 | 256P FLOPS+ |

### 软件栈：CANN

> **CANN 就是昇腾生态里的 CUDA。**

| 层 | 作用 |
|---|---|
| 驱动层 Driver | 管理 NPU 设备资源 |
| 运行时 Runtime/NNRT | 任务调度、内存管理 |
| 算子库 AICPU/TBE | 数千个优化算子 |
| 编程接口 AscendCL | C/C++ 统一接口 |
| **框架适配层** | PyTorch(torch_npu) / TensorFlow / MindSpore |

### 全栈方案

```text
应用层    ModelArts · 盘古大模型
    ↑
平台层    CANN + MindSpore
    ↑
系统层    openEuler
    ↑
硬件层    昇腾 NPU + 鲲鹏 CPU
```

> 💡 **全栈的优势**：各层深度协同优化，比"异构拼装"性能更稳。openEuler 针对鲲鹏和昇腾做了内核级调优。

### 管理命令：npu-smi

> **相当于 GPU 的 nvidia-smi。**

```bash
npu-smi info              # 查看设备信息（最常用）
npu-smi info -t usages -i 0   # 看 0 号卡的利用率
watch -n 0.5 npu-smi info     # 每 0.5 秒刷新
```

Python 里检查：
```python
import torch, torch_npu
torch.npu.is_available()
torch.device('npu:0')
```

## 🐋 三、DeepSeek 生态

### 发展历程

| 时间 | 版本 | 突破 |
|---|---|---|
| 2023.11 | Coder | 代码能力超越同期 ChatGPT |
| 2024.5 | **V2** | 首创 **MLA** + DeepSeekMoE |
| 2024.12 | **V3** | 达到 GPT-4o 水平，成本仅数十分之一 |
| 2025.1 | **R1** | 强化学习驱动推理，对标 o1 |

### 四项核心技术

| 技术 | 做了什么 | 效果 |
|---|---|---|
| **MLA** | KV 压缩到低维潜在空间 | KV Cache **↓93.3%** |
| **DeepSeekMoE** | 更细粒度专家 + 共享专家 | 能力保住，算力可控 |
| **FP8 训练** | 大规模 FP8 混合精度 | 吞吐 **+40%** |
| **多 Token 预测** | 一次预测多个后续 token | 加速收敛 |

> 🎯 **这四项全是冲着"降本"去的**。
> 记住这个判断：**DeepSeek 的护城河不是参数多，而是同等效果下算力省**。

### 三种使用方式

| 方式 | 特点 | 适合 |
|---|---|---|
| **官方 API** | 兼容 OpenAI，**价格约为 GPT-4 的 1/30** | 快速开发 |
| **本地部署** | HuggingFace/ModelScope + vLLM | 数据敏感、长期大量用 |
| **国产化部署** | torch_npu + vLLM | 自主可控要求 |

## ☁️ 四、端-边-云协同

### 三层定位

| 层 | 位置 | 优势 | 劣势 |
|---|---|---|---|
| **端** | 手机、摄像头 | 极低延迟、隐私好 | 算力小 |
| **边** | 园区机房、路侧 | 低延迟、省带宽、数据不出园区 | 中等算力 |
| **云** | 数据中心 | 算力最强 | 延迟高、带宽贵 |

### 分级策略（这套思路很实用）

| 维度 | 端侧 | 边缘 | 云端 |
|---|---|---|---|
| **任务** | 简单（关键词、人脸） | 中等（目标检测） | 复杂（多轮对话） |
| **模型** | 1B 蒸馏小模型 | 7B 轻量模型 | 70B+ 完整模型 |
| **数据** | 原始数据初处理 | 摘要信息分析 | 关键数据+难任务 |

### 典型场景选型

| 场景 | 选型 | 原因 |
|---|---|---|
| 智慧园区 | **边缘为主** | 视频数据量大，不能全上云 |
| 智能客服 | **云端为主** | 需要强语言理解 |
| 自动驾驶 | **端+边** | 端侧感知，路侧融合 |
| 医疗影像 | **边+云** | 边缘初筛保隐私，疑难上云 |

> 🎯 **选型三原则**（记住这句就够了）：
> **延迟敏感的就近处理，数据敏感的本地处理，计算密集的集中处理。**

<details>
<summary>参考答案</summary>
