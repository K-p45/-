## 🔗 贯穿全课的四条主线

### 线索一：**「换模型只改两个参数」**

```text
第1章  国内模型都兼容 OpenAI 接口
第3章  base_url + api_key 就够了
第6章  本地 vLLM 也是同一个接口
第2章  vLLM serve 起来就是 OpenAI 格式
```

> 🎯 这是**整个生态能繁荣的技术基础**。学会一套，通吃所有。

### 线索二：**「显存决定一切」**

| 章节 | 显存相关 |
|---|---|
| 第2章 | 权重 + KV Cache + 20% 余量 |
| 第4章 | 两个公式，16G 卡只能跑 7B INT8 |
| 第2章 | 量化不是省显存，是**换并发** |

```text
权重显存 = 参数量 × 字节数
KV Cache = 2 × 层 × 头 × 维 × 长度 × 并发 × 字节
```

> 这两个公式贯穿第 2 和第 4 章，**会算就能选对**。

### 线索三：**「先检索，再生成」**

```text
第5章  优化顺序：先固检索根基
第5章  四指标诊断：context 低 → 检索；faithful 低 → 生成
第8章  Workflow 主干 + Agent 灵活决策 —— 同样的先稳后活
```

> 🎯 **一个通用原则**：**先把输入质量做好，再谈输出质量**。Garbage In, Garbage Out。

### 线索四：**「能画完流程图就用 Workflow，画不完用 Agent」**

```text
第6章  Agent 适合多步操作 + 工具 + 判断
第7章  Workflow 一次产出 vs ChatFlow 多轮交互
第8章  混合架构：Workflow 做主干，Agent 填坑
```

> 这条经验法则能在无数技术选型里套用：**能穷举的用确定性方案，穷举不了的才上智能方案**。

## 🎯 四张速查表

### 环境速查（第2章）

| 场景 | 命令 |
|---|---|
| 看 NPU | `npu-smi info` |
| 看 GPU | `nvidia-smi` |
| 跑模型 | `ollama run xxx` / `vllm serve xxx` |
| 容器 | `docker run -d -p 8000:8000` |

### 显存选型（第4章）

| 硬件 | 首选 |
|---|---|
| 16GB 单卡 | 7B INT8 |
| 32GB 单卡 | 14B FP16 / 32B INT8 |
| 64GB 双卡 | 32B FP16 / 72B INT8 |

### RAG 指标诊断（第5章）

| 指标低 | 改谁 |
|---|---|
| context_recall | 检索器（补文档、换 Embedding、查询改写） |
| context_precision | 检索器（重排序、调分块） |
| faithfulness | 生成器（提示词约束、事实核查） |
| answer_relevancy | 生成器（问题分类、摘要压缩） |

### 监控四指标（第8章）

| 指标 | 目标 |
|---|---|
| TTFT | < 1 秒 |
| TPS | 30-60（7B 单卡） |
| **P99 延迟** | 看它，不看平均 |
| QPS | 容量规划 |
