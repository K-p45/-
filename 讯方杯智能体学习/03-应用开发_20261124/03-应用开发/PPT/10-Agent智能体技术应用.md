## 第 5 页

- 一、Agent（智能体）概述
- 普通的大模型对话（如 ChatGPT 聊天）本质上是"一问一答"——你提一个问题，模型给一个回答，然后等你的下一个问题。模型是被动的，它不会主动去做任何事情。
- Agent（智能体）则不同，它是一个能够自主规划、使用工具、持续执行的 AI 系统。
- 假设需要完成"帮我查一下明天北京的天气，如果气温低于 10 度就帮我在日程里加一条带厚外套的提醒"这个任务，普通对话只能告诉你天气预报信息，Agent 则会自动调用天气 API 查询、判断温度、调用日历 API 添加提醒——整个过程不需要你逐步指挥。

## 第 7 页

- 一、Agent（智能体）概述
- 从技术角度对比：普通对话的输入是用户问题，输出是文本回答，没有外部交互。Agent 的输入是用户目标，输出是任务完成结果，过程中会调用工具、读取数据、执行操作。
- Agent 与普通对话的区别
- 类比来说，普通对话像是"顾问"——只能给你建议；Agent 像是"助理"——不仅给建议，还帮你执行。从能力边界来看，普通对话受限于模型的训练知识；Agent 通过工具可以访问实时信息、操作外部系统，能力边界大大扩展。

![[Agent智能体技术应用/幻灯片7.PNG]]

## 第 8 页

- 二、Agent 的基本架构
- Agent 的架构可以概括为四个核心环节：感知（Perceive）→ 规划（Plan）→ 行动（Act）→ 反馈（Reflect），形成一个循环。
- 感知：接收用户的指令和环境信息。
- 规划：大模型作为"大脑"，分析任务并制定执行计划——需要分几步完成？每一步用什么工具？
- 行动：按计划调用工具执行具体操作。
- 反馈：检查执行结果是否符合预期，如果不符合就调整计划重新执行。这个"规划-行动-反馈"的循环是 Agent 区别于普通对话的核心机制。

![[Agent智能体技术应用/幻灯片8.PNG]]

## 第 9 页

- 二、Agent 的基本架构
- Agent 系统由四个核心组件构成。
- 核心组件
- 大脑（LLM）：负责理解任务、推理和决策，通常使用 GPT-4、DeepSeek-V3 等能力强的大模型。模型的推理能力越强，Agent 的规划能力越好。
- 手脚（Tools）：Agent 可以调用的外部工具，比如搜索引擎、计算器、代码执行器、数据库查询等。工具让 Agent 的能力从"说"扩展到"做"。
- 经验（Memory）：Agent 的记忆系统，包括短期记忆（当前对话上下文）和长期记忆（历史交互记录）。
- 思维（Prompt）：定义 Agent 行为的系统提示词，包括角色设定、工具使用规则和行为约束。

## 第 10 页

- 三、Agent 类型
- 根据架构和能力的不同，Agent 可以分为几种类型。
- 单 Agent：一个 Agent 独立完成所有任务，适合简单场景。依赖模型，可以使用插件、工作流、知识库、MCP服务等工具，让模型自主规划，使用不同工具完成指定任务。
- 多 Agent 协作：多个 Agent 分工合作，每个 Agent 负责不同的子任务。可配置多个工作流，侧重根据客户意图在不同工作流中进行选择和跳转。
- ReAct 型 Agent：采用"推理+行动"交替的模式，每一步都先思考再行动。
- 从实际应用来看，大部分场景用单 Agent 就能满足需求。多 Agent 适合复杂的工作流——比如一个"研究员 Agent"负责搜索信息，一个"写手 Agent"负责撰写内容，一个"审核员 Agent"负责检查质量。CrewAI 和 AutoGen 是目前最流行的多 Agent 框架。

![[Agent智能体技术应用/幻灯片10.PNG]]

## 第 11 页

- 四、Agent 适用场景
- Agent 最适合需要"多步操作"和"工具协调"的场景。比如：
- 智能客服——查询订单状态、处理退换货、调用工单系统；
- 数据分析——读取数据文件、编写分析代码、生成可视化图表；
- 编程助手——理解需求、搜索文档、编写代码、执行测试。
- 不太适合 Agent 的场景包括：纯文本生成（写文章、翻译）、简单问答（不需要工具的知识问答）。判断标准是：如果任务可以通过一次对话完成，不需要 Agent；如果任务需要多步操作、外部工具调用、条件判断，Agent 就是更好的选择。

## 第 13 页

- 一、Function Calling 机制
- 工作流程：开发者先告诉模型有哪些函数可用（函数名、参数说明、用途）；用户提出问题后，模型判断是否需要调用函数；如果需要，模型输出函数名和参数（JSON 格式）；系统执行函数并将结果返回给模型；模型基于函数结果生成最终回答。
- 比如用户问"北京今天天气怎么样？"，模型会请求调用 get_weather(city="北京") 函数，获取实时天气数据后再回答。
- Function Calling（函数调用）是 Agent 使用工具的基础机制。它让大模型能够在对话过程中"请求调用"一个外部函数，并将函数的返回结果纳入回答。

![[Agent智能体技术应用/幻灯片13.PNG]]

## 第 14 页

- 二、常见工具类型
- Agent之所以能像一位能干的助手那样完成任务，关键在于它可以灵活调用各种外部工具。工具就像是Agent的“手脚”，扩展了它的能力边界，让它不仅能“说”，还能“做”。根据功能的不同，Agent可使用的工具可以分为以下几类：
- 搜索工具：调用搜索引擎获取实时信息（如 Google Search API、Bing API）。
- 代码执行工具：运行 Python 代码进行数据处理和计算。
- 数据库工具：查询和操作数据库（如 SQL 查询）。
- API 调用工具：调用各种第三方 API（天气、地图、支付、消息推送等）。
- 文件操作工具：读取和写入文件（PDF 解析、Excel 处理等）。
- 知识库检索工具：从 RAG 知识库中检索信息。工具的数量和质量直接决定了 Agent 的能力边界——工具越丰富，Agent 能完成的任务类型就越多。

## 第 15 页

- 三、记忆系统
- Agent的记忆系统是它能够进行连贯对话、持续学习和自我进化的核心机制。与人类记忆类似，Agent的记忆也分为三个层次：短期记忆、长期记忆和工作记忆，它们各司其职，共同支撑起Agent的智能行为。

![[Agent智能体技术应用/幻灯片15.PNG]]

## 第 16 页

- 三、记忆系统
- 上下文窗口是有限的，不可能把所有历史记录都放进去。常见的记忆管理策略包括：
- 对话摘要：当对话历史太长时，用大模型对早期对话生成摘要，用摘要替代原文，在保留关键信息的前提下减少 token 占用。
- 评分机制：给每条记忆打"重要性"分数，只保留最重要的记忆。
- 遗忘机制：类似人类的记忆衰减，时间越久的信息权重越低，最终可能被删除。在 Dify 平台中，可以设置"对话轮数上限"和"记忆窗口大小"来控制短期记忆的范围。
- 记忆管理策略
- 策略 | 优点 | 缺点 | 适用场景
- 对话摘要 | 大幅压缩token | 可能丢失细节 | 长对话、客服会话
- 滑动窗口 | 实现简单 | 丢失早期信息 | 通用对话
- 重要性评分 | 保留关键信息 | 需要额外计算 | 个性化助手
- 分层存储 | 成本与速度平衡 | 实现复杂 | 大规模知识库
- 元数据过滤 | 检索精准 | 需维护元数据 | 企业数据检索
- 遗忘机制 | 控制数据膨胀 | 可能误删有用信息 | 长期运行的系统

## 第 17 页

- 四、规划能力
- Agent 面对复杂任务时，需要将大任务分解为可执行的子任务。
- 比如"帮我写一份关于 DeepSeek-V3 的技术分析报告"可以分解为：
- 1. 搜索 DeepSeek-V3 的技术论文和官方博客；
- 2. 提取关键技术点（MoE 架构、MLA 注意力、训练成本等）；
- 3. 与 GPT-4、LLaMA-3 等模型进行性能对比；
- 4. 整理成报告格式。
- 大模型的规划能力取决于它的推理能力。GPT-4 和 DeepSeek-R1 在复杂任务分解方面表现较好，而较小的模型可能会遗漏步骤或者规划不合理。在实际开发中，可以通过提示词来引导模型进行更好的任务分解。

## 第 18 页

- 五、反思与纠错
- Agent 在执行过程中可能会犯错——比如调用了错误的工具、解析结果不正确、生成的代码有 bug。反思（Reflection）机制让 Agent 能够检查自己的执行结果，发现错误后自动调整策略。
- 一个典型的反思流程：
- Agent 执行一步操作 → 检查结果是否符合预期 → 如果不符合，分析原因（工具选错了？参数不对？思路有误？）→ 制定新的计划 → 重新执行。
- 这种自我纠错能力是 Agent 相比简单的工具链更智能的地方。在 Dify 中，可以通过设置"最大迭代次数"来控制 Agent 的重试上限，避免无限循环。

![[Agent智能体技术应用/幻灯片18.PNG]]

## 第 19 页

- 六、ReAct 模式
- ReAct（Reasoning + Acting）是目前最主流的 Agent 执行模式。它的核心思想是让大语言模型（LLM）不仅能“回答问题”，还能通过交替进行推理和行动，主动规划、调用工具、获取信息、迭代思考，最终解决复杂任务

![[Agent智能体技术应用/幻灯片19.PNG]]

## 第 20 页

- 六、ReAct 模式
- ReAct一步都包含三个部分：
- Thought（思考）——模型分析当前状态，决定下一步做什么；
- Action（行动）——调用一个工具执行操作；
- Observation（观察）——获取工具返回的结果。
- 以"查询 DeepSeek-V3 的参数量"为例：
- Thought: 我需要搜索 DeepSeek-V3 的技术参数。
- Action: search("DeepSeek-V3 参数量 架构")
- Observation: DeepSeek-V3 拥有 6710 亿参数，采用 MoE 架构... Thought: 找到了答案，可以回复用户了。
- 这种"思考-行动-观察"的循环会重复进行，直到 Agent 认为任务完成。

![[Agent智能体技术应用/幻灯片20.PNG]]

## 第 21 页

- 七、MCP 协议
- MCP（Model Context Protocol，模型上下文协议）是 Anthropic 提出的标准化工具接入协议。它的目标是解决一个实际问题：每个 Agent 框架都有自己的工具接口格式，开发者接入一个新工具就要适配不同的格式，非常麻烦。
- MCP 定义了一套统一的协议标准，让工具开发者只需要实现一次接口，就能被所有支持 MCP 的 Agent 框架调用。这就像 USB 接口统一了外设连接标准一样。
- 目前 Dify、LangChain、Claude Desktop 等平台都已支持 MCP 协议。对于开发者来说，MCP 大幅降低了工具开发和集成的成本。

![[Agent智能体技术应用/幻灯片21.PNG]]

## 第 22 页

- 八、多 Agent 协作
- 在复杂任务中，单个 Agent 可能力不从心，这时可以让多个 Agent 协作完成。一个经典的多 Agent 架构是"研究员+写手+审核员"模式：
- 研究员 Agent：负责搜索信息、收集资料、整理数据。
- 写手 Agent：基于研究员提供的资料，撰写内容。
- 审核员 Agent：检查写手的输出，指出错误和不足，要求修改。
- 这三个 Agent 协作的效果通常优于单个 Agent 独立完成所有工作，因为每个 Agent 可以专注于自己擅长的部分。CrewAI 和 AutoGen 是目前最流行的多 Agent 协作框架，它们提供了 Agent 之间的通信和任务分配机制。

![[Agent智能体技术应用/幻灯片22.PNG]]

## 第 23 页

- 二、CrewAI 与 AutoGen
- CrewAI 的核心概念是"角色扮演"——每个 Agent 被赋予一个角色（如"市场分析师"、"技术写手"），并配备对应的工具和背景知识。多个 Agent 组成一个"Crew"（团队），按照预定义的流程协作。CrewAI 的代码风格简洁直观，适合快速搭建多 Agent 原型。
- AutoGen 由微软研究院开发，强调 Agent 之间的"对话式"协作——Agent 之间通过消息传递来协调工作，类似于人类团队的讨论模式。AutoGen 支持人机协作（Human-in-the-Loop），允许人类在关键节点介入决策。
- 两个框架各有特色：CrewAI 更适合流程明确的场景，AutoGen 更适合需要灵活协商的场景。

## 第 25 页

- 一、Dify Agent 开发步骤
- 使用 Dify 平台开发 Agent 应用的基本步骤：
- 第一步，创建一个"Agent"类型的应用（不是"聊天助手"类型）。
- 第二步，选择底层大模型（推荐 DeepSeek-V3 或 GPT-4，推理能力要强）。
- 第三步，编写系统提示词，定义 Agent 的角色和行为规则。
- 第四步，添加工具——Dify 内置了搜索、代码执行、HTTP 请求等工具，也支持自定义 API 工具。
- 第五步，配置知识库（如果需要 RAG 能力）。
- 第六步，测试和调优——通过对话测试 Agent 的行为，根据效果调整提示词和工具配置。

![[Agent智能体技术应用/幻灯片25.PNG]]

## 第 26 页

- 二、工具与知识库配置
- 在 Dify 中配置 Agent 的工具时，每个工具需要提供清晰的描述——这个描述是大模型判断"什么时候该用这个工具"的依据。
- 比如一个天气查询工具的描述应该是"查询指定城市的当前天气和未来 3 天天气预报"，而不是简单的"天气工具"。
- 知识库与 Agent 的结合方式：在 Agent 的工具列表中添加"知识库检索"工具，Agent 可以在需要时主动查询知识库。因此，它比固定在每次对话中都检索知识库更灵活——Agent 会判断用户的问题是否需要查知识库，只在需要时才检索，减少不必要的开销。

![[Agent智能体技术应用/幻灯片26.PNG]]

## 第 27 页

- 三、工作流设计
- 常见的节点类型包括：LLM 节点（调用大模型生成文本）、知识库检索节点（执行 RAG 检索）、条件分支节点（根据条件选择不同路径）、代码执行节点（运行 Python/JavaScript 代码）、HTTP 请求节点（调用外部 API）。
- 通过将这些节点串联起来，可以构建复杂的业务逻辑，比如"先检索 → 判断是否找到结果 → 找到则生成回答 / 未找到则调用搜索引擎"。
- Dify 提供了工作流（Workflow）功能，可以用可视化的方式编排 Agent 的执行流程。工作流由一系列节点（Node）组成，每个节点执行一个特定的操作。

## 第 30 页

- 六、技术展望
- Agent技术正在从“被动响应”走向“主动执行”，从“单一技能”走向“通才协作”。当前，Agent的发展呈现出三个相互交织的重要方向：计算机使用（Computer Use）、自主学习（Self-Evolution）和多模态感知（Multi-modal Perception）。这三个方向共同推动着Agent从“对话工具”向“生产力工具”的跨越。
- 计算机使用（Computer Use）：Agent 直接操作电脑界面——点击按钮、输入文本、截屏理解，就像一个远程操作电脑的助手。Claude、GPT-4 已经具备了初步的能力。
- 自主学习：Agent 可以从执行经验中学习和改进，不再需要人工手动优化提示词和工具配置。
- 多模态 Agent：结合视觉、听觉和文本能力，Agent 可以理解图片、视频和语音中的信息。从产业角度来看，Agent 被视为大模型从"对话工具"走向"生产力工具"的关键一步。
